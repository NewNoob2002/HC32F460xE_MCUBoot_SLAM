# SLAMRTK Charge Board V1.0 hardware archive

This directory is the board-level source of truth for firmware pin ownership.
The primary source is `SLAMRTK_Chargeborad_V1.0.pdf` (one A2 page, PDF
metadata date 2026-08-10, SHA256
`07e75363b1b97b2df771b024f825e3bc89c33713d4e4083df9a75c22b23e73b5`).

## MCU and clocks

- MCU: HC32F460JEUA, QFN48.
- Main crystal: Y3, 8 MHz.
- RTC crystal: Y2, 32.768 kHz.
- MCU supply: `VCC_3V3`; the 3.3 V rail is generated by U11 SCT2432STER.

## Firmware pin map

| MCU pin | Signal/net | Direction | Firmware use |
| --- | --- | --- | --- |
| PA4 | `CHARGE_STAT1` | input | Charger status |
| PA5 | `PG` | input | Power-good indication |
| PA6 | `WDOG_DONE` | output | TPL5010 watchdog feed pulse |
| PB0 | `PSYS` | analog input | MP2762A system-power monitor |
| PB1 | `MP2762_IAM` | analog input | MP2762A input-current monitor |
| PB2 | `MP2762_IBM` | analog input | MP2762A battery-current monitor |
| PA8 | `I2C2_SDA` | bidirectional | MP2762A/HUSB238 and board I2C |
| PA9 | `I2C2_SCL` | bidirectional | MP2762A/HUSB238 and board I2C |
| PA11 | `USB_DM` | bidirectional | USB FS D- |
| PA12 | `USB_DP` | bidirectional | USB FS D+ |
| PA13 | `SWDIO` | bidirectional | SWD debug |
| PA14 | `SWCLK` | input | SWD debug clock |
| PB12 | `USART1_RX` schematic net | input | Debug UART RX test point TP1; not used by current logger |
| PB13 | `USART1_TX` schematic net | output | Debug UART TX test point TP2 |

The UART net names in the schematic are logical labels. PB12/PB13 use the
HC32 PB function group, where `GPIO_FUNC_32/33` route USART3 TX/RX. Firmware
therefore uses `CM_USART3`, PB13 TX with function 32, and (if later needed)
PB12 RX with function 33. Do not select `CM_USART1` from the net label alone.

## Debug and log access

- J1 is the three-pin SWD header: ground, SWCLK through R8 (0 ohm), and SWDIO
  through R9 (0 ohm).
- TP1 is the debug UART RX net; TP2 is the debug UART TX net.
- Debug firmware logs on TP2 at 115200 baud, 8 data bits, no parity, one stop
  bit, 3.3 V TTL.
- For passive log capture connect USB-UART RX to TP2 and share ground. Do not
  connect a 5 V UART signal to the board.
- The 2026-08-28 Debug UART HIL verified firmware registers and the DAPLink VCOM
  self-loop but captured no TP2 bytes. Treat the physical PB13/TP2 path as
  unverified until idle-voltage/waveform and continuity measurements are made;
  see `evidence/hil/2026-08-28-469f9ca-phase5-debug-uart/`.

## USB and update path

- USB FS uses PA11/PA12 and the USB-C connector J3.
- J3 CC1/CC2 also connect to the HUSB238 controller (U10).
- Firmware USB identities and WinUSB descriptors are software contracts; keep
  them in `Config/ProductIdentity.env` and the Phase 5 ADRs, not in this board
  pin table.

## Watchdog

- External watchdog: U4 TPL5010DDCT.
- `DONE` is driven by PA6 through R18 (0 ohm).
- `RSTn` reaches `MCU_RESET` through R17 (0 ohm).
- The schematic note specifies a 60 s watchdog interval. Current firmware
  pulses DONE for 1 ms every 3 s, leaving margin before the external deadline.

## Charger and external signals

- Charger: U9 MP2762A, controlled on I2C2.
- Charger-related MCU inputs are `CHARGE_STAT1`, `PG`, `PSYS`,
  `MP2762_IAM`, and `MP2762_IBM` as listed above.
- Test points include TP8 `CHARGE_STAT`, TP12 `MP2762_IAM`, TP13
  `MP2762_IBM`, TP15 `PROCHOT`, TP16 `PSYS`, TP10 `MCU_RESET`, and TP11
  ground/reference beside the reset network.
